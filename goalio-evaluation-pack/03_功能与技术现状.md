## 3. 页面与核心组件

项目只有一个实际路由 `/`。入口链：

`HomePage → GoalioInviteApp → GoalioAccountApp → AuthScreen / GoalioApp`

业务页集中在 `features/app/GoalioApp.tsx`：欢迎、收入、饮食、固定支出、目标、余额、首页、消费输入、消费结果、设置、目标完成、购买后余额和完成页。页面分派在 `GoalioApp.tsx:643-677`。

核心组件与模块：

- `GoalioInviteApp`：邀请码授权；
- `AuthScreen`：注册登录表单；
- `GoalioAccountApp`：会话、缓存、云同步、退出；
- `GoalioApp`：完整业务状态机；
- `PressableButton`：加载/成功反馈按钮；
- `runSimulation`：统一目标模拟；
- `evaluatePurchase`：消费影响模拟；
- `GoalioSyncCoordinator`：本地优先同步。

## 4. 状态管理

- 未使用 Redux、Zustand 或其他外部状态库。
- 主业务状态由 `GoalioApp` 内部 React state 管理；每次变化调用 `onStateChange`。
- 账号、加载阶段和同步状态由 `GoalioAccountApp` 管理。
- `GoalioState` schema 版本为 1，保存页面位置、计划、余额、历史快照、上次结果、变化量和当前消费输入。

证据：`features/app/GoalioApp.tsx:605-633`、`features/account/GoalioAccountApp.tsx:58-69`、`lib/storage/schema.ts:22-32`。

## 5. 数据保存与同步

### 当前生产路径

1. 每次业务状态变化先写入用户隔离的 localStorage 缓存；
2. 缓存键为 `goalio:user:<userId>:v1`；
3. 缓存内容含 `state`、`savedAt`、`pendingSync`；
4. 默认 500ms 防抖后将整份状态 upsert 到 Supabase；
5. 云端每个用户一行，状态保存在 JSONB；
6. 网络恢复或页面重新获得焦点时重试；
7. 退出前尝试完成同步，失败时阻止退出；
8. 退出成功清除当前用户的本机缓存。

来源：`lib/account/user-cache.ts`、`lib/account/sync.ts`、`features/account/GoalioAccountApp.tsx`、`lib/account/supabase.ts`。

### 旧存储代码

`lib/storage/storage.ts` 使用旧键 `goalio:v1` 并提供损坏数据恢复和旧教程支出清理。当前生产入口没有引用它，仍有单元测试覆盖。

### 未使用

当前未发现 IndexedDB、Service Worker、后台同步、BroadcastChannel 或离线应用清单。

## 6. 外部 API、后端与数据库

- 浏览器直接调用 Supabase Auth 和 `goalio_states` 表。
- 未发现 Next.js API Route、Route Handler、Server Action 或自建 HTTP 后端。
- 数据库 migration 创建 `public.goalio_states`，主键为 `user_id`，删除 Auth 用户时级联删除状态。
- RLS 已在 migration 中定义：匿名用户无表权限，authenticated 用户只能读写自己的记录。
- 仓库只使用公开 Supabase URL 与 Publishable Key，没有高权限服务密钥。

代码证据能够确认设计与迁移文件；线上数据库是否已准确执行 migration 仍需要后台核验。

## 7. 登录注册

当前支持：

- 邮箱密码注册；
- 邮箱密码登录；
- 保持会话和自动刷新 token；
- 仅退出当前设备。

当前未发现：

- 找回或重置密码；
- 修改密码或邮箱；
- 邮箱确认流程 UI；
- OAuth、短信登录；
- 用户自行删除账号。

README 要求 Supabase 关闭 Confirm Email，以便注册后直接获得 session。来源：`README.md:15-25`、`lib/account/supabase.ts:25-60,99-115`。

## 10. 部署配置

- `next.config.ts`：`output: "export"`、`trailingSlash: true`、可选 `PAGES_BASE_PATH`；
- 两套 GitHub Actions 工作流都在 main push 或手动触发时构建并部署 Pages；
- 两套工作流都使用 base path `/Goalio`，并注入两个 Supabase 公开环境变量；
- 当前线上 URL 已在 2026-09-27 实际打开：`https://l93854524-cell.github.io/Goalio/`。

两套 workflow 使用相同 concurrency group，其中一套取消进行中的任务，另一套保留；同时触发时存在相互竞争的配置风险。当前工作流只执行安装和构建，没有 test 或 lint gate。

## 11. 当前可直接验证的技术限制

- 只有一个目标；
- 币种固定为人民币；
- 预测最多 3650 天；
- 必要预留观察窗固定为 365 天；
- 安全购买日期只搜索未来 365 天；
- 固定支出 UI 只能新建月度规则；
- 收入数据类型支持结束日期，UI 没有输入结束日期；
- 多设备同时编辑使用整份 JSONB 覆盖，缺少版本合并或冲突提示；
- 同步新旧比较依赖客户端 `savedAt` 与服务器 `updatedAt` 字符串，设备时间偏差可能影响选择；
- 邀请码公开在前端包中，只能作为轻量入口；
- 完成页没有创建下一目标的入口；
- 没有支付、订单、分析和错误监控；
- 没有完整自动化 E2E；
- 两套 Pages 工作流重复；
- 本地仓库缺少 `.env.local`，本地业务全流程无法连接真实 Supabase；线上页面可以访问。
