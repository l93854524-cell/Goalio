# Goalio 明日安全消费保护设计

## 目标

首页给出的明日消费金额必须保护已经展示的目标进度。用户按照首页建议消费并按计划支付基本开销后，下一次更新余额时，目标进度不得因为这笔建议内消费而回撤。

## 产品承诺

- `EffectiveGoalSaved` 是已经为目标留好的钱，优先级高于自由消费。
- 首页字段改为“明天额外最多可花”，强调它是基本开销之外的自由消费金额。
- 该金额已经同时保护未来必要生活费、固定支出和当前目标进度。
- 在余额、收入、支出和目标规则均未发生其他变化时：
  - 实际额外消费不超过上限，下一次更新不得因该消费降低目标进度。
  - 实际额外消费超过上限 ¥1，目标进度最多因该消费降低 ¥1。
- 自然日推进仍可按照原有节奏增加目标进度；安全容量不足时仍允许立即回撤。
- 大额消费评估继续允许用户模拟超过首页上限的消费。只要消费会动用当前目标进度，结果页必须优先显示目标进度减少的金额；完成日期未变化也不能归类为“无影响”。

## 算法

首页明日消费上限继续使用整数二分搜索。每个候选金额作为明日的一次额外消费加入统一模拟器，并且必须同时满足：

1. 未来必要生活费和固定支出有足够预留。
2. 预计完成日期不晚于目标截止日。
3. 模拟后的 `EffectiveGoalSaved` 不低于当前页面展示的 `EffectiveGoalSaved`。

第三条把当前目标进度作为消费上限的保护底线。明日基本开销已经包含在 `RequiredReserve` 中，不从“额外最多可花”中重复扣除。

## 页面

- “明天最多可以花”改为“明天额外最多可花”。
- 配套说明改为：“这个金额不包含明天的基本开销，也不会动用已为目标留好的钱。实际余额或计划变化后会重新计算。”
- 当前计划无法按期完成时，继续隐藏该金额并显示调整提示。
- 大额消费会动用已留好的钱时，结果页显示“会动用已留好的钱”“目标进度减少 ¥X”，并说明消费前后的目标进度和预计完成日期。

## 验证

- 算法单元测试覆盖：按上限消费后目标进度保持；超出 ¥1 后只回撤 ¥1。
- 消费评估测试覆盖：完成日期相同但目标进度减少时，不得返回“无影响”。
- 页面集成测试覆盖新字段名称和保护说明。
- 运行全部测试、代码检查和正式构建。
