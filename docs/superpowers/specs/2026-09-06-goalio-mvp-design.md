# Goalio 手机网页 MVP 设计说明

## 1. 目标

构建一个手机优先、可完整操作的 Goalio MVP。产品围绕四个连续任务展开：首次设置、每日余额更新、目标进度理解、额外消费评估。界面、文案和交互以 `final-design-reference`、`GOALIO_COPY_GUIDE.md` 与 `GOALIO_DIRECTION.md` 为基准。

首版交付应允许用户从欢迎页进入四步设置，填写首次余额，查看每日结果，评估一笔消费，修改设置，并完成目标。财务数据保存在浏览器本地。邀请码采用可演示的本地校验适配层，并为后续服务端接入保留接口。

## 2. 产品范围

### 包含

- 欢迎页与邀请码输入
- 四步首次设置：未来收入、每日饮食、固定支出、单一目标
- 首次余额输入
- 每日余额输入和当日重复更新
- 目标进度、今日变化、预计完成日期、明日生活安排
- 消费名称与金额输入、影响结果与两类替代方案
- 设置查看、修改和重新安排
- 目标完成与购买后余额更新
- 浏览器本地持久化
- 开发环境日期控制台
- 移动端和桌面窄栏响应式体验

### 暂缓

- 真实邀请码数据库、用户账号与多设备同步
- 银行、支付平台或账单自动同步
- 多目标、消费流水和复杂统计图表
- 服务端保存任何用户财务数据

## 3. 技术方案

采用 Next.js、TypeScript 和 CSS Modules 建立单一前端项目。应用由以下模块组成：

- `app`：页面入口、全局样式和应用容器
- `components`：按钮、金额输入、选项列表、步骤页框架、结果行、底部操作区等通用界面单元
- `features/onboarding`：四步设置与首次余额流程
- `features/dashboard`：每日输入、结果页和目标完成状态
- `features/purchase`：消费评估输入和结果
- `features/settings`：设置汇总和重新安排
- `lib/simulation`：纯 TypeScript 金额、日期与逐日预测逻辑
- `lib/storage`：带版本号的本地数据读写与迁移
- `lib/time`：生产日期和 Demo 日期的统一来源
- `lib/invitation`：邀请码验证接口；MVP 提供本地演示实现

金额全部使用整数分。核心模拟函数接收显式 `today` 参数。页面通过统一状态层调用模拟器，首页与消费评估共享计算口径。

## 4. 页面与导航

页面顺序遵循 12 张参考图：

1. 欢迎：品牌、价值表达、开始设置、邀请码入口
2. 未来收入：周期选择、金额、下次到账日期、无确定收入入口
3. 每日饮食：大金额输入、解释文本
4. 固定支出：支出列表、增加和删除
5. 攒钱目标：名称、金额、目标日期
6. 当前余额：首次真实余额、隐私说明、计算提交
7. 每日余额：当日日期、余额输入、重复更新提示
8. 首页结果：目标金额、进度条、今日变化、完成日期、次日额度、消费入口
9. 消费输入：商品名称、金额、提交评估
10. 消费结果：影响结论、延期天数、解释、降低预算与延后购买
11. 设置：四类设置摘要、编辑入口、重新安排
12. 目标完成：100% 视觉状态、确认购买、继续保留、购买后余额

导航使用轻量状态路由。首次设置支持返回上一页，已填写内容保留。主页、消费评估和设置之间使用明确的返回关系，浏览器刷新后恢复当前业务状态。

## 5. 视觉系统

- 系统字体栈优先使用 SF Pro、PingFang SC 和平台系统字体
- 主色为黑、白、Apple Blue `#007AFF`
- 页面最大内容宽度约 430px，桌面端居中呈现，手机端占满可用宽度
- 标题大、行距紧凑；说明文字使用中性灰；关键金额拥有最高视觉权重
- 控件采用 16–24px 圆角、1px 浅灰边框和极轻阴影
- 页面一次突出一个任务，维持宽松垂直留白
- 选择状态使用参考图中的蓝色描边和纤细蓝色竖线
- 目标完成页使用黑白强对比，其余页面保持明亮背景
- 避免彩色渐变、玻璃效果、装饰性图标和密集卡片堆叠

## 6. 交互与按钮反馈

按钮反馈是首版的重点验收项。所有可点击元素共享统一交互语言：

### 主按钮

- 默认：Apple Blue 背景、白字、清晰可见的触屏热区
- 按下：在 90ms 内缩放到 `0.975`，亮度轻微降低，阴影收敛
- 松开：以约 180ms 的弹性缓动恢复
- 键盘焦点：显示 2px 蓝色外圈，确保键盘操作可见
- 禁用：降低不透明度并保持文案清晰，不响应点击
- 提交中：文字平滑切换为指南中的处理中内容，显示轻量加载指示，锁定重复提交
- 成功：短暂出现确认状态，再进入下一页；页面跳转与按钮恢复保持连续
- 失败：按钮轻微水平反馈一次，在输入区下方显示具体原因，保留用户已填写内容

### 次要按钮与列表项

- 文本按钮按下时透明度降至约 55%，松开后恢复
- 列表项按下时背景过渡为浅灰，右侧箭头轻微向前移动
- 返回、关闭和箭头按钮拥有至少 44×44px 热区
- 选项切换时，蓝色描边和竖线在 160ms 内完成过渡

### 页面与数据变化

- 前进页面从右侧轻移并淡入，返回时方向相反，距离控制在 12–18px
- 页面离开前完成输入校验；存在错误时聚焦首个错误字段
- 金额结果使用数字缓动更新，进度条同步增长或回撤
- 结果区按信息层级依次出现，避免整个页面同时闪现
- 弹层与底部操作区进入时使用 220ms 上移动画，并支持背景点击关闭
- 检测到 `prefers-reduced-motion` 时关闭缩放、位移和数字缓动，只保留短淡入与即时状态变化
- 触摸反馈依赖 CSS 状态与指针事件，不依赖移动浏览器延迟明显的点击机制

## 7. 数据模型与计算

核心数据包含：收入规则、每日饮食金额、固定支出、单一目标、余额记录、有效目标进度、最近计算日期、购买评估输入和设置版本。

计算链遵循：

`真实余额 → 未来现金流 → 必要预留 → 安全目标容量 → 有效目标进度 → 预计完成日期`

首版模拟器实现以下约束：

- 当日已发生收支包含在真实余额中，预测从次日开始
- 基本生活与固定支出优先，目标资金随后，自由消费最后
- 同日重复输入相同余额得到相同进度，余额变化时立即重算
- 历史进度仅用于解释本次变化，不限制当前安全容量
- 目标进度处于 0、目标金额和安全容量共同限定的区间内
- 未来信息缺失保留为显式未知状态
- 消费评估通过加入候选消费后重新运行逐日模拟器
- 无影响最高金额使用整数二分搜索
- 最早无影响购买日期使用逐日扫描

在详细算法原文尚未加入项目时，MVP 使用方向文件明确的保守预测规则，并将模拟器边界隔离，方便后续替换公式。

## 8. 本地持久化与隐私

所有余额、收入、支出和目标数据写入浏览器本地存储，使用版本化数据结构并提供安全默认值。服务端适配层只处理邀请码状态，不接收财务字段。设置页明确说明数据只保存在当前设备。

本地存储不可用或数据损坏时，页面给出清楚提示，并允许用户重新开始。任何错误都不应静默覆盖现有数据。

## 9. Demo 日期控制

开发与 Demo 构建可显示日期控制台，用于前进或后退自然日并验证连续变化。正式构建通过独立环境开关移除入口，业务页面只能读取系统当前日期。测试会确认正式环境无法修改日期。

## 10. 错误处理

- 金额输入拒绝负数、超长数字和超过两位的小数
- 日期输入验证收入、支出和目标的时间关系
- 信息不足时展示缺少的具体字段
- 计算异常时保留输入并提供重试
- 存储异常时提示数据未保存，避免给出成功反馈
- 邀请码错误区分无效、已绑定和临时连接失败

## 11. 测试与验收

### 自动测试

- 金额转换、整数分运算和格式化
- 收入与固定支出的周期展开
- 必要预留、安全容量和目标资金分配
- 同日确定性、跨日现金流变化和余额下降回撤
- 未知状态传播
- 消费延期、无影响金额和最早无影响日期
- 本地存储序列化、版本恢复和异常处理

### 界面测试

- 12 个页面的主路径与返回路径
- 表单校验、加载锁和防重复提交
- 每类按钮的按下、恢复、禁用、成功与失败状态
- 320px、375px、390px、430px 及桌面窄栏布局
- 键盘焦点、44px 热区、对比度和减少动态效果
- 刷新后状态恢复与正式构建日期控制隔离

### 视觉验收

逐页与参考图对照，重点检查内容宽度、页边距、标题比例、关键金额大小、留白、边框、圆角、按钮高度、蓝色选择状态和页面转场。交互验收使用真实浏览器录屏或连续截图确认反馈过程。

## 12. 完成定义

用户可以顺畅走完首次设置，在手机上每日更新真实余额，理解目标进度和次日安排，评估额外消费，查看替代方案，修改设置并完成目标。所有关键点击都有即时、克制、连续的反馈；刷新后数据仍在；核心计算测试通过；正式构建无法启用 Demo 日期控制。
