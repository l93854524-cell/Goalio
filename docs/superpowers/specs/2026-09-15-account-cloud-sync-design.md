# Goalio 账号与云端同步设计

## 1. 目标

为 Goalio 增加零月费的邮箱密码账号体系，让每位新用户拥有独立资料。用户首次注册后完成一次初始设置；同一设备再次打开时自动保持登录并进入当日流程；换设备后重新登录即可恢复收入、固定支出、目标、余额和每日记录。

当前产品是部署在 GitHub Pages 的 Next.js 静态站点。账号与云端数据采用 Supabase 免费档，网页继续保持静态部署，不新增自有服务器。

## 2. 已确认的产品决策

- 登录方式：邮箱与密码。
- 注册后直接进入首次设置。
- 当前设备长期保留登录会话，用户主动退出前无需重复登录。
- 换设备后使用同一邮箱和密码恢复完整资料。
- 只设计新用户流程，不迁移浏览器里已有的旧资料或演示资料。
- 首版不发送注册确认邮件，以避开发信服务费用。
- 首版不提供自助密码找回；忘记密码时由产品管理者在 Supabase 管理后台协助处理。
- 当前设备保留用户专属缓存，用于快速启动和短暂离线。
- 多设备同时修改时，以最后一次成功同步的数据为准。

## 3. 用户流程

### 3.1 首次注册

1. 用户打开 Goalio，看到品牌说明以及“注册”“登录”入口。
2. 用户选择注册，输入有效邮箱和至少 8 位密码，并再次确认密码。
3. 注册成功后建立登录会话，并创建该用户的空白 Goalio 云端记录。
4. 用户进入现有四步设置流程，随后填写首次真实余额。
5. 每一步都写入用户专属本地缓存；网络可用时同步到云端。
6. 首次设置完成后进入首页。

邮箱已注册、密码不符合要求、两次密码不一致、请求过于频繁或服务暂时不可用时，页面保留输入并显示可操作的中文错误信息。

### 3.2 日常打开

1. 应用启动后先恢复本机登录会话。
2. 有有效会话时读取该用户的云端状态。
3. 云端读取成功后，以云端状态进入应用；当天尚未更新余额时直接进入每日余额页。
4. 云端暂时不可用且存在该用户缓存时，进入缓存状态并显示“等待同步”。
5. 云端暂时不可用且没有缓存时，停留在重试页，禁止用空白状态覆盖云端资料。

### 3.3 换设备与退出

- 新设备登录成功后读取同一用户的云端记录并恢复完整流程状态。
- 设置页显示当前账号邮箱、同步状态和“退出登录”。
- 退出只结束当前设备的会话，并清除该用户在当前设备上的业务缓存。
- 退出不会删除云端资料，也不会影响其他已登录设备。

## 4. 系统结构

### 4.1 前端边界

新增三个职责清晰的单元：

- `auth`：注册、登录、恢复会话、监听会话变化和退出。
- `cloud-state`：读取、创建和保存当前用户的 Goalio 状态。
- `user-cache`：按用户 ID 隔离本机缓存，并记录是否存在待同步修改。

应用入口先完成身份初始化，再挂载业务界面。`GoalioApp` 继续负责现有页面和业务状态，只通过状态仓库读取初始值、提交变更和展示同步结果。

### 4.2 Supabase 客户端

静态网页使用 `@supabase/supabase-js` 浏览器客户端。构建时只注入以下可公开配置：

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

客户端开启会话持久化和令牌自动刷新。`service_role` 等管理密钥不得写入仓库、GitHub Pages 构建变量或浏览器代码。

### 4.3 数据表

建立 `goalio_states` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | `uuid` | 主键，关联 `auth.users.id` |
| `state_version` | `integer` | Goalio 状态结构版本 |
| `state` | `jsonb` | 完整的 Goalio 业务状态 |
| `updated_at` | `timestamptz` | 最近一次云端写入时间 |

每个用户最多一行。数据库为 `user_id` 建立主键索引，开启 Row Level Security，并分别为读取、新建和更新设置策略。所有策略都要求 `(select auth.uid()) = user_id`。匿名角色不拥有该表权限，已登录角色只获得业务需要的 `select`、`insert` 和 `update` 权限。

### 4.4 本地缓存

现有单一键 `goalio:v1` 退出业务读写路径。新缓存键包含用户 ID，例如 `goalio:user:<user-id>:v1`。缓存外层记录：

- `state`：通过运行时校验的 `GoalioState`。
- `savedAt`：客户端写入时间。
- `pendingSync`：本地是否有尚未成功提交的变化。

身份初始化前不得读取任何业务缓存。退出时只清除当前用户对应的键，防止同一浏览器中的下一位用户读取前一位用户资料。

## 5. 数据读取与同步

### 5.1 登录后的首次读取

1. 取得已验证的当前用户，并读取该用户的本地缓存。
2. 请求该用户的 `goalio_states` 行，返回状态和云端 `updated_at`。
3. 本地存在待同步状态且 `savedAt` 晚于云端 `updated_at` 时，载入本地状态并立即重试同步，避免离线修改被旧云端状态覆盖。
4. 其他情况下，存在云端记录时校验 `state_version` 和状态结构，再载入业务界面并刷新本地缓存。
5. 云端记录不存在时，优先恢复该用户有效的待同步缓存；没有缓存时创建 `createInitialState()`，显示首次设置欢迎页，并写入云端和本地缓存。
6. 云端数据无效时进入保护性错误页，保留本地缓存且不自动覆盖云端。

### 5.2 修改与自动保存

业务状态每次变化时立即保存到用户专属本地缓存，并标记 `pendingSync: true`。云端写入经过短暂合并，减少连续输入造成的请求数量。写入成功后刷新云端时间并将缓存标记为已同步。

浏览器恢复网络、页面重新获得焦点或应用再次启动时，只要发现待同步缓存，就重新提交。页面卸载前不依赖最后一次网络请求作为唯一保存手段，本地缓存始终先完成。

### 5.3 冲突规则

首版采用整份状态最后写入覆盖。应用不支持同一账号在两台设备上同时编辑的合并；最近一次成功提交到云端的完整状态成为后续读取结果。界面文案会提醒用户等待“已同步”后再切换设备。

## 6. 界面设计

### 6.1 身份页面

新增与现有 Goalio 视觉系统一致的身份页：大标题、单一主要任务、清晰输入框和底部主按钮。注册与登录通过顶部文本切换，避免在同一屏堆叠两套表单。

注册字段：

- 邮箱
- 密码
- 确认密码

登录字段：

- 邮箱
- 密码

密码默认隐藏，提供可访问的显示与隐藏控制。提交期间锁定按钮，失败后保留邮箱并清空密码字段。

### 6.2 启动与同步反馈

- 身份与数据初始化期间显示 Goalio 启动画面，避免短暂闪现欢迎页。
- 设置页显示“已同步”“等待同步”或“同步失败，点击重试”。
- 离线编辑期间保留业务操作能力，并在固定位置提示资料尚未上传。
- 首次云端读取失败且没有缓存时显示重试入口，不进入空白首次设置。

### 6.3 文案与隐私

现有“资料只保存在当前设备”的说明改为“资料会加密传输并保存到你的 Goalio 账号，当前设备同时保留一份缓存”。不承诺客户端无法提供的数据库静态加密能力，也不展示技术密钥名称。

## 7. 错误处理

- 未配置公开 Supabase 环境变量：显示服务未配置提示，业务界面不启动。
- 会话过期且刷新失败：回到登录页，保留云端资料，清除当前设备会话和业务缓存。
- 注册邮箱已存在：引导用户切换到登录。
- 登录凭据错误：使用统一提示，避免泄露账号是否存在。
- 云端读取失败：有缓存时进入离线状态；无缓存时只允许重试或退出。
- 云端保存失败：保留本地数据和待同步标记，提供手动重试并监听网络恢复。
- 云端状态版本过高或结构损坏：阻止载入与覆盖，显示联系维护者的提示。
- 本地缓存损坏：丢弃该缓存后重新读取云端，不影响云端记录。

## 8. 安全与隐私

- 所有云端读写均携带当前 Supabase 会话，由数据库 RLS 执行用户隔离。
- 前端只使用 publishable key；管理密钥只保存在 Supabase 管理环境。
- 密码由 Supabase Auth 处理，Goalio 业务表、本地业务缓存和日志都不保存密码。
- 退出调用当前设备范围的登出，避免把其他设备一并退出。
- 日志和错误提示不得包含余额、收入、支出、目标内容、访问令牌或密码。
- 首版关闭邮箱确认，需要在发布说明中明确密码找回由管理者协助。

## 9. 零成本边界

- Supabase 免费档覆盖首版所需的 Auth、Postgres 数据库和静态网页 API 调用额度。
- 免费项目连续一周无活动可能暂停，产品管理者可在控制台恢复。
- Supabase 默认发信服务只面向项目团队邮箱，且当前限制为每小时两封，不适合公开用户注册。
- 首版关闭注册确认邮件和自助密码找回，因此无需接入付费短信或邮件服务。
- 未来需要自助找回密码时，再接入自有 SMTP 服务；该扩展不属于本次实现。

## 10. 测试与验收

### 10.1 单元与组件测试

- 新用户注册成功后进入首次设置。
- 已登录用户刷新后跳过登录页。
- 已完成设置的用户在新设备登录后恢复云端状态。
- 两个用户在同一浏览器中的缓存键和读取结果完全隔离。
- 退出清除当前用户缓存并保留其他账号缓存之外的无关浏览器数据。
- 状态变化先写本地，再触发合并后的云端保存。
- 离线修改被标为等待同步，网络恢复后自动补传。
- 云端读取失败且无缓存时不会创建或上传空白状态。
- 云端状态损坏时不会覆盖本地有效缓存。
- 注册、登录、保存和重试错误显示正确且保留可恢复输入。
- 现有首次设置、每日更新、消费评估和设置流程继续通过。

### 10.2 数据库验收

- 未登录请求无法读取、新建或更新 `goalio_states`。
- 用户 A 无法读取或修改用户 B 的记录。
- 用户只能创建 `user_id` 等于自身身份 ID 的记录。
- 业务前端使用 publishable key 可以完成当前用户的读取、新建和更新。

### 10.3 手动验收

1. 使用邮箱 A 注册，完成初始设置并确认同步状态为“已同步”。
2. 刷新页面，确认直接回到业务流程。
3. 在第二个浏览器登录邮箱 A，确认完整资料恢复。
4. 在第二个浏览器更新余额，等待同步后刷新第一个浏览器，确认能读取最新数据。
5. 退出邮箱 A，确认无法看到其业务资料。
6. 注册邮箱 B，确认看到全新的首次设置流程。
7. 断网后修改资料，确认出现“等待同步”；恢复网络后确认转为“已同步”。

## 11. 发布与配置

仓库提供 Supabase 建表与 RLS 迁移 SQL、环境变量示例和配置说明。GitHub Actions 从仓库 Secrets 注入公开 URL 与 publishable key 完成静态构建。正式发布前需要在 Supabase 控制台：

1. 创建免费项目。
2. 执行仓库提供的数据库迁移。
3. 启用邮箱密码注册并关闭邮箱确认。
4. 将 GitHub Pages 正式地址加入允许的站点地址。
5. 在 GitHub 仓库 Secrets 中配置两项公开连接值。
6. 使用两个真实测试账号完成账号隔离与跨设备验收。

## 12. 完成定义

一位全新用户可以注册账号、完成首次设置并成功同步；同一设备再次打开无需登录；另一台设备登录后恢复完整资料；每个账号的数据彼此隔离；断网修改不会丢失，并在网络恢复后自动同步；退出后当前设备不再显示该用户资料；现有 Goalio 业务测试、代码检查和静态构建全部通过。
